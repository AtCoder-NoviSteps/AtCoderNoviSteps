# PCKの問題番号とコンテスト別一覧表

## 決定事項

`staging` の `34e712c4` から作成済みの `feat/pck-contest-tables` で実装した。
ユーザーの指示によりDBリセット・再シードは対象外とし、実際にも実行していない。
既存の `ContestType.AOJ_PCK`、AOJクライアント、Provider基底クラス、JAG用の表レイアウトを再利用し、新しいContestTypeやSvelteコンポーネントは追加しなかった。
PCKの `problem_index` はコンテストごとにAOJ問題IDの数値昇順で `1` からの数字文字列とする。AOJ問題IDとURLは変更しない。
予選は2004〜2026年の23大会263問、本選は2003〜2025年の23大会318問、計581問を収録する。
「PCK 予選」「PCK 本選」の独立グループをJAGの後に登録し、各年度の見出しを `PCK 2026 予選` などとして新しい年度から並べる。
同じ年度の予選・本選は `AOJ_PCK::Prelim2025` / `AOJ_PCK::Final2025` のようにProviderキーを分けた。
JAG用の共有ソートを数値対応にし、`1, 2, …, 10` の順に問題を配置する。タイトルの番号は既存の描画処理で付け、元タイトルを変更しない。
シードに581問を追加し、再シード不要で適用できるデータマイグレーションも追加した。未登録の問題を追加し、登録済みのPCK問題では表示番号と更新日時だけを変更する。
登録済みID、タイトル、グレード、投票・回答の関連は維持する。異なるコンテスト・ContestTypeに属する同一task_idは上書きしない。同じ番号が既に設定されている行も更新しない。
本番へのマイグレーション適用は既存CIの経路を使用する。

## データ出典と判断

- 既存のAOJ APIフィクスチャには予選2004〜2025年と本選2003〜2025年が収録されていた。
- AOJの指定APIへの接続はこの実行環境からは名前解決に失敗したため、ユーザーが貼り付けた公式APIレスポンスで最新年度を確認した。
- 予選2026年の12問をそのレスポンスからフィクスチャへ追加した。本選の最新は提供レスポンスに従って2025年とし、2026年本選は推測して追加しなかった。
- 予選2026年は `4084` が1番、`4086` が3番、`4095` が12番となる。依頼の例示では4086が1番だったが、提供された公式一覧の先頭は4084だった。
- AOJ掲載問題に対して連番を付ける。例えば本選2011年はAPI掲載の3問を1〜3とし、未掲載問題の元の位置は復元しない。
- 元のAPIに含まれる統計値はグレードの推定に使わず、新規問題のグレードはDB既定のPENDINGとする。

## 採用しなかった案

- 表示時だけAOJ問題IDを連番に置換する案は、DB・出典ラベル・今後の取り込みで番号が一致しないため採用しない。
- 予選・本選のContestType新設やPCK専用の表コンポーネントは、既存の仕組みで足りるため追加しない。
- DBに存在する問題だけを `ROW_NUMBER()` で採番する案は、一部の問題しか登録されていない大会で番号がずれるため採用しない。全掲載問題から確定した対応をマイグレーションに保持する。
- シード再実行だけでは登録済み問題の番号が更新されず、ユーザーも再シード不要としたため、非破壊のUPSERTでデータを反映する。
- 外部APIの統計値の変動まで既存の全JSONへ反映する作業や、汎用的なProvider生成機構の導入は行わない。

## 検証結果

- 番号変換、クライアント、数値順ソート、Provider、グループ登録、シード整合性のテストを先に追加し、未実装・旧番号・文字列順による失敗を確認してから実装した。
- マイグレーションの581行とシードのPCK581問は (id, contest_id, problem_index, title) が完全に一致し、task_idの重複はない。
- ローカルのPostgreSQL開発DB（PCK 8大会96問、全件が旧形式）でマイグレーションをトランザクション内で実行してロールバックした。1回目は581行（更新96・追加485）、2回目は0行で、旧形式の行は残らなかった。
- 実装時にSQLiteのメモリDBで同じ性質を確かめるテストを書いたが、適用後に変更しないマイグレーションを別エンジンで再現するだけなので削除した。
- 全単体テストはSQLiteのテスト削除後に104ファイル3025件成功した。
- `pnpm format`、`pnpm lint`、`git diff --check` は成功した。
- 現行の `staging` とマージした状態で、警告も失敗扱いの `pnpm check` はエラー・警告とも0件、`pnpm lint` と単体テストも成功した。
- `.env` の読み取り拒否は解除せず、秘密情報を含まない一時コピーで単体テスト・型チェック・ビルドを実行した。SvelteKitの生成型設定とPrismaの生成ファクトリもそのコピーに配置した。
- ホストNode 25.2.1ではVercelアダプターが奇数バージョンを拒否した。既存のNode 24.15.0による一時コピーのビルドは、Vercelアダプターを含めて完走した。プロジェクト指定のNode 26でのCI検証は残る。
- PCK両グループの切替と再読み込み後の選択保持を確認するE2Eを追加したが、通常のE2E起動は同じホストNode 25のビルド制約によりWebServerの起動前に失敗した。
- 2026-11-03にClaudeがレビューし、Codexがクロスレビューした。Codexの指摘は0件だった。ユーザーの選択により、E2Eのテスト名の英語化とSQLiteテストの削除を反映した。
- 別コンテスト・別ContestTypeに同じtask_idがある行を通知なしでスキップする点は、現状起こり得ないため対応しない。シードのテストをAOJクライアントの隣に置くのは意図どおりである。
