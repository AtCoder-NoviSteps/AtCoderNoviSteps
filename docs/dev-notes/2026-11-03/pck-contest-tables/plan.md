# PCKの問題番号とコンテスト別一覧表

PCK（パソコン甲子園）の問題番号を、AOJ問題IDからコンテストごとの連番に変えた。あわせて予選・本選の年度別一覧表を追加し、全581問をシードとデータマイグレーションでDBにそろえた。

## 決定事項

- 番号はAOJに掲載された問題だけに振り、未掲載問題の元の位置は復元しない。例えば本選2011年は掲載された3問を1〜3とする。
- reset・再シードを不要にするため、データはマイグレーションのUPSERTで反映する。
- 未登録の問題はstaging・本番でもグレードPENDINGで追加される。これはレビュー後にユーザーが了承した。
- 新規問題のグレードは、AOJ APIの統計値から推定しない。

## データ出典

- 既存のAOJ APIフィクスチャには、予選・本選とも2025年までが入っていた。
- 実装環境からAOJ APIに接続できなかったため、ユーザーが貼り付けた公式APIレスポンスから予選2026年の12問を追加した。本選2026年はレスポンスになかったため追加していない。
- 依頼の例では予選2026年の1番は `4086` だったが、公式一覧の先頭が `4084` だったためそちらに従った。

## 採用しなかった案

- 表示時だけ問題IDを連番に置き換える案：DB・ラベル・今後の取り込みで番号が食い違う。
- ICPC・JAGと同じく、`ROW_NUMBER()` でDB上の問題だけを採番するUPDATE：未登録の問題を追加できない。追加にはタイトルも要るため、全581問の一覧をSQLに埋め込んだ。
- 再シードで反映する案：シードは登録済みの `task_id` をスキップするため、既存問題の番号が更新されない。
- 予選・本選用のContestType新設やPCK専用のコンポーネント：既存の仕組みで足りる。
- 既存JSONの統計値の更新や、汎用的なProvider生成機構：今回の目的に不要。

## 検証とレビュー

- マイグレーションの581行は、シードの581問と (id, contest_id, problem_index, title) が一致し、`task_id` の重複はない。
- ローカルのPostgreSQL（適用前はPCK 8大会96問、全件が旧形式）で、ロールバック前提の試行と本適用を行った。581行に作用し（更新96・追加485）、旧形式の行は0件になった。2回目の実行では0行だった。
- 適用後のローカルDBで、PCK両グループのE2E 2件が成功した。現行の `staging` とマージした状態で、単体テスト・lint・check（警告も失敗扱い）も成功した。
- Claudeがレビューし、Codexがクロスレビューした（Codexの指摘は0件）。
- 対応しないと決めた点：別コンテストに同じ `task_id` がある行は通知なしでスキップされるが、現状は起こり得ない。シードのテスト `seed_problem_numbers.test.ts` をAOJクライアントの隣に置くのは意図どおりである。
- 未確認：staging・本番の既存データに対する適用結果。
