**状態**: PR0 完了（#4212）・PR1 完了（#4217）・PR1.5 完了（#4219）・PR2 は staging に反映（#4220、本番は未反映）。全体像は [plan.md](./plan.md)、根拠データは [investigation.md](./investigation.md)。

コードと git の履歴から読み取れない判断と事実だけを残す。変更したファイルや関数は #4212 / #4217 / #4219 / #4220 の差分を見る。PR1.5 は [こちら](#pr15--aoj-api-の移転に追従する4028)、PR2 は [こちら](#pr2--jag-合宿系と-jag-模擬地区を問題記号にする4030)。

## 何をしたか

- **PR0**: 出典欄の AOJ 分岐を `${contestName} - ${taskTableIndex}（AOJ）` にし、AOJ のコンテスト名ラベルから全角括弧を外した
- **PR1**: ICPC 国内予選 / アジア地区 / JAG 模擬国内（79 コンテスト / 632 問）の `task_table_index` を問題記号にした。移行 SQL は `prisma/migrations/20261024033928_update_aoj_task_table_index/`。管理画面の取り込みでも、この範囲は基本ルールで記号を付ける。表示側の変換（`buildAojLetterMap` / `AOJ_LABEL_OVERRIDES` / `formatAojTitle` / `getTaskLabels`）は削除した

## 決定と理由

| 決定                                                                    | 理由                                                                                                                                                                                                           |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 移行 SQL は対応表を焼き込まず、基本ルールを SQL で表す                  | 本番のタスクは管理画面の取り込みで入っており、seed と一致する保証が無い。`VALUES` で書くと本番にしか無い行が残り、`UPDATE` は該当行が無くてもエラーにならないので、取りこぼしが静かに起きる                    |
| 範囲は `contest_type` ではなく `contest_id` の接頭辞で絞る              | 合宿系も模擬国内と同じ `AOJ_JAG` に分類される。`contest_type` だけで絞ると合宿系 467 件まで更新し、title のプレフィックスが表に出る                                                                            |
| 取り込みでは、対応表ではなく基本ルールで記号を付ける（M5）              | 対応表を AOJ client に置く案は、毎年の新しいコンテストで追記が要り、忘れると数値の index が黙って入る。`prisma/tasks.ts` と同じ情報を 2 か所に持つことにもなる                                                 |
| 表示側の変換と `getTaskLabels` を削除する（M7 / M10）                   | DB が記号を持てば変換は恒等になる。インターフェイスの `getTaskLabels` だけを残す案は、上書きする Provider が 0 になり使われないコードが残るので採らなかった                                                    |
| ヘッダーの並びは `localeCompare`（M4）                                  | 記号に `Number()` を当てると NaN になり、ソートが効かなくなる                                                                                                                                                  |
| AOJ ラベルから全角括弧を外す（M11）                                     | 出典欄の目標書式ではコンテスト名を括弧で囲まない。ラベルは検索・投票・タグ・取り込み画面・提出状況の更新モーダルでも使われており、その表示も変わるが許容した                                                   |
| `buildTitleWithTaskIndex` は「外してから付ける」                        | AtCoder 側の title は `A. …` を含むので、付けるだけだと二重になる。title にプレフィックスの無い AtCoder の問題は `abs` の practice_1 だけで（本番も同じ）、ABS は index を表示しない                           |
| `removeTaskIndexFromTitle` は先頭のプレフィックスだけを消す（レビュー） | 記号は title の本文にも現れうる。以前は index が空のとき `Dr. Podboq` → `DrPodboq` のように本文の `. ` まで消していた                                                                                          |
| `AOJ-KUPC2011` の 2279 は title だけを素にし、index（`I`）は触らない    | 本番でも index は既に正しい。AOJ に 1 問しか無いので、大学系に範囲を広げるときは基本ルール（`A` になる）の対象から外す                                                                                         |
| PR0 → PR1 → 合宿系の順にする                                            | PR0 は DB に依存しない。PR1 は出典欄の成果がすぐ見え、欠落が少ないので対応表の形式を楽なケースで決められる。逆順はレビュー負荷が低いが、出典欄の反映が遅れ、対応表の形式を最も判断の重い合宿系で作ることになる |

## 検証で分かったこと

- **2 日開催の JAG 模擬国内**: AOJ API には `JAGPrelim20162`（2738–2751）のように 2 日を 1 コンテストにしたものがある。取り込みは `contest_id` 単位で振るので A–N になる。seed と本番は `JAGPrelim2016A` / `B` に分かれており、取り込みは既存の問題を skip するので影響しない

## PR1.5 — AOJ API の移転に追従する（#4028）

### 何をしたか

- `AOJ_API_BASE_URL` を `https://judgeapi.u-aizu.ac.jp/` から `https://onlinejudge.u-aizu.ac.jp/api/` に変えた。旧ホストは 410 を返し、管理画面からの AOJ の取り込み（Courses / PCK / JAG / ICPC）がすべて失敗していた
- `clients.test.ts` のクライアントを本番の定数から作り、nock で受ける URL（`/api/…`）を期待値として直書きした。`nock.disableNetConnect()` も足した
- 開発コンテナの外向き通信の許可リスト（`.devcontainer/init-firewall.sh`）の `judgeapi.u-aizu.ac.jp` を `onlinejudge.u-aizu.ac.jp` に置き換えた

### 決定と理由

| 決定                                                   | 理由                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 変えるのはベース URL だけ                              | AOJ Developers の告知（2026-09-07 に Main API が移転）で変わったのはホストだけ。メンテナが新しい API をブラウザで開き、取り込みが使う 8 つのエンドポイント（`courses`、`problems?size=10000`、`challenges` の 6 種別）のパスと応答の形が fixture と同じことを確かめた |
| fixture は取り直さない                                 | 応答の形が同じため。取り直すと統計値（`solvedUser` など）や新しい回の追加で差分が出て、fixture に依存するテストの期待値まで変わる                                                                                                                                     |
| テストは nock のまま、クライアントを本番の定数から作る | CI で実 API を叩かないために nock でモックするのはメンテナの意図どおりで、そのまま残す。問題は、テストが自前の旧ホストからクライアントを作っていて、定数を間違えても通ることだった                                                                                    |
| `nock.disableNetConnect()` を足す                      | モックを書き忘れたリクエストが、黙って実 API に飛ぶのを防ぐ                                                                                                                                                                                                           |
| 許可リストの旧ホストは残さず、新しいホストに置き換える | 旧ホストは 410 を返すだけで使い道が無い。許可先はデータを持ち出せる経路でもあるので、数を増やさない                                                                                                                                                                   |

### 検証で分かったこと

- **応答の違い**: 値の違いは最上位の `largeCl.id` が小文字になったこと（`"JAG"` → `"jag"` など）だけ。コードはここを読まない。fixture に無い回（ICPC 国内予選 2026、JAG 模擬国内 2026、PCK 予選 2026 など）は、fixture の記録（2026-05）の後に AOJ に追加されたもの
- **ベース URL の落とし穴**: `new URL(endpoint, base)` は、ベースの末尾に `/` が無いか、エンドポイントの先頭に `/` があると `/api` を落とす。旧ホストはパスが無かったので表に出ていなかった
- **テストの検出力**: `AOJ_API_BASE_URL` の 4 つの変異（末尾の `/` を外す、旧ホストに戻す、`/api/v1/` にする、`/api` を外す）は、どれも 26 件すべてのテストで検出された
- **問題ページへのリンク**: `https://onlinejudge.u-aizu.ac.jp/problems/{id}` は今のまま開ける（メンテナが確認）
- **合宿系の API**: JAG の filter には summer / winter / spring もあるが、既存の contest_id にそろえるアドホックな対応が多いので、応答の形は意図的に確かめていない（[plan-pr2-1.md](./plan-pr2-1.md#csv)）
- **開発コンテナからの 500**: ベース URL を変えた後も、ローカルの管理画面の取り込みが 500 になった。開発サーバーはコンテナの中で動き、外向き通信は許可リスト方式で、新しいホスト（163.143.87.177）が入っていなかった（旧ホストは 163.143.87.219）。サーバーの `fetch` が接続で拒否され、管理画面のアクションが `fail(500)` を返していた。ブラウザはホストの Mac から直接開くので見えていた
- **許可リストの反映**: `init-firewall.sh` は Dockerfile の `COPY` でイメージに入り、起動時に 1 回だけ DNS で IP を引く。編集を反映するには、コンテナの再起動ではなく再ビルドが要る

### 残っている確認

- ~~コンテナを再ビルドした後、ローカルの管理画面で AOJ から取得できること~~ — 2026-10-24 にメンテナが確認した
- ~~staging（Vercel）での取り込み~~ — 2026-10-24 にメンテナが JAG REGIONAL を取り込み、16 / 158 になった（[PR2](#pr2--jag-合宿系と-jag-模擬地区を問題記号にする4030) の前提）。こちらの取得ツールが新しいホストに `ECONNREFUSED` で拒まれたことから送信元の制限を心配していたが、Vercel からは問題なく取得できた

## PR2 — JAG 合宿系と JAG 模擬地区を問題記号にする（#4030）

### 何をしたか

- JAG 合宿系（夏 / 冬 / 春、50 コンテスト / 467 問）と JAG 模擬地区（16 / 158）の `task_table_index` を、問題 ID から問題記号にした。合宿系の title から、前に付いていた `<問題 ID>. ` を外した。移行 SQL は `prisma/migrations/20261025000719_update_aoj_jag_task_table_index/`
- seed に、本番だけにあった模擬地区 158 問を足した（grade は本番のまま。3355 の title は trim）
- 管理画面の取り込みで、JAG は全 round（模擬国内 / 模擬地区）で記号を付けるようにした
- 記号の対応表は、メンテナのスプレッドシートを書き写した照合スクリプトで作った（`git show c605d3bd:docs/dev-notes/2026-09-09/task-title-index-change-impact/generate_aoj_jag_problem_letters.ts`）

### 決定と理由

| 決定                                                                                                        | 理由                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 基本ルールで振り、8 コンテストはコンテストの全行を上書きする（45 行）                                       | 8 コンテストは先頭や途中の問題が AOJ に無く、基本ルールでは記号がずれる。正しい記号は、メンテナのスプレッドシートの位置（欠けた問題を飛ばした位置）で決まる。全行を上書きするのは、1 つのコンテストに 2 つの規則を混ぜないため |
| 各ステップの更新件数を DO ブロックで検査し、想定外なら RAISE する                                           | UPDATE は対象が 0 件でもエラーにならない。想定値は、空の DB（`prisma migrate reset`）の 0、模擬地区の無い開発 DB の 467 / 32 / 467、staging・本番の 625 / 45 / 467                                                             |
| 件数は固定値のまま。模擬地区が一部だけの DB では RAISE し、エラー文で「全部取り込むか、全部消す」と案内する | 本番で範囲の誤りを止める力を保つため。模擬地区だけ実際の件数に合わせる案は、範囲の誤りを見逃しやすくなるので採らなかった                                                                                                       |
| 順位はコンテストの全行で付け、更新は問題 ID のままの行だけにする                                            | 後から記号付きで入る行（PR2.1）が先にあっても触らないため。順位を付ける側でも絞ると、記号の行と問題 ID の行が混ざったコンテストで A から振り直してしまう（Codex の指摘）                                                       |
| title から外すのは「自分の `task_id` + `. `」で始まるものだけ                                               | `^[0-9]+\. ` で外すと、番号で始まる本来の title まで削りうる                                                                                                                                                                   |
| 範囲は `contest_id` の接頭辞（`^JAG(Summer\|Winter\|Spring\|Regional)`）で絞る                              | `AOJ_JAG` には PR1 で記号にした模擬国内も含まれる                                                                                                                                                                              |
| 取り込みでは補正しない（M14）                                                                               | 8 コンテストは本番・staging・seed のすべてにあり、取り込みは既存の問題を skip する。Codex も「取り込みで補正すべき」と指摘したが、同じ理由で採らなかった                                                                       |
| seed の検査は、補正した 8 コンテストを literal で、title を「問題名（`name`）と同じ」で見る                 | 補正の正しさは基本ルールの関数では検査できない。title は「問題 ID が前に付いていない」だけだと、空や別の問題の title にすり替わっても通る（Codex の指摘）                                                                      |
| 前後に空白のある title（本番 46 件、3355 の末尾のタブを含む）は直さない                                     | 表示では空白が潰れ、完全一致で比べるコードも無い。取り込みが trim するので再発もしない（[plan.md](./plan.md#スコープ外)）                                                                                                      |

### 検証で分かったこと

- **staging の準備**: staging には当初、模擬地区が 2 コンテスト / 16 問しか無く、件数チェックで RAISE するところだった。PR1.5 の後に staging で取り込み、PR を開く前に本番と同じ状態（模擬地区 16 / 158、合宿系 50 / 467、index はすべて問題 ID、title の問題 ID は合宿系だけ）であることを確かめた
- **seed の模擬地区**: 本番から取り出した 158 問は、AOJ の fixture（2026-05 記録）と問題 ID・コンテスト・名前がすべて一致した
- **照合**: スプレッドシートの書き写し（66 コンテスト）と 625 問の title が、記号の位置ですべて一致した。補正は 8 コンテスト / 45 行（事前の目視どおり）。わざと誤りを入れたコピー 5 種類（欠けた記号を外す、順番の入れ替え、途中の title の誤り、欠けた数の不足、切れた title の前半の誤り）はすべて検出された
- **ローカルでの移行**: 管理画面で模擬地区を取り込み、本番と同じ状態にしてから確かめた。`SELECT` のプレビューは 625 行すべてで照合の結果と一致し、適用後もプレビューと 625 / 625 で一致した。範囲外の AOJ（PCK、大学系、PR1 の範囲）は変わらない。`EXPLAIN` は CTE 側の Seq Scan 1 回と、`task_task_id_key` の Index Scan を使う Nested Loop
- **Codex の指摘の再現**: 記号の行と問題 ID の行が混ざったコンテストを読み取り専用で再現すると、直す前の SQL は A から振り直し、直した後は B, C, D と正しく振った。ローカルは移行前のスナップショットに戻し、直した移行を適用し直した（625 / 625）
- **テストの検出力**: 6 つの変異をすべて検出した（JAG の記号を PRELIM だけ / ICPC だけにする、補正した記号を基本ルールに戻す、基本ルールのコンテストで A・B を入れ替える、title に問題 ID を付け直す、模擬地区の記号を問題 ID に戻す）。title のテストは、空の title・別の問題の title・問題 ID の付け直しも検出する
- **Codex の他の指摘**: 「`task_id` だけで結合している」は、`task_id` が schema で `@unique` なので該当しない

### 残っている確認

- ~~staging~~ — #4220 で反映した（2026-10-25）。移行の後に Vercel のデプロイが走るので、件数チェックも通っている
- 本番（`main` への昇格後）で、移行が通ること
- 問題一覧の出典欄の表示（例: `JAG 夏合宿 2024 Day3 - H（AOJ）`）
