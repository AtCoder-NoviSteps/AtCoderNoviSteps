3-1 で決めること:

- **`available` が 1 でない問題の扱い**。3643 は 2026-10-10 に AOJ に追加されたばかりで、`available` が 4、提出が 0。公開前の状態なら、AOJ のコンテスト一覧に入った後で管理画面の取り込みで入れられるかもしれない。手で INSERT するか、一覧に入るのを待つかを決める。先に `available` の値の意味と、判明分（1123 を含む）の値を確かめる

3-2 で決めること:

- **`task_id` の採番**。AOJ に無い問題には ID が存在しないため、衝突しない採番規則が要る
- **問題へのリンク先**: JAG のサイト（jag-icpc.org）の大会区分のページ（例: `2008/Practice/模擬地区予選`）にする。21 問のコンテストすべてにあり、5 ページで済む（[一覧と構成](./investigation.md#欠落の一覧pr3)）
  - 理由: 提出先が無いので、自分で採点するには問題文だけでなくジャッジデータと講評も要る。大会区分のページからはどれにも下りられる。逆に、深いページに着地したユーザーは上の階層にほぼ戻らない（PDF には戻る手段すら無い）ので、入口のページが見つけられる範囲を決める。階層が浅いほど、下位ページ名や添付ファイル名の変更でリンクが切れる箇所も、URL 中の日本語も減る
  - 不採用: PDF への直リンク（問題文までは 1 クリックだが講評に辿れない。添付ファイル名が `day1.pdf` / `problems.pdf` と揃っていない）。`問題文とデータセット` のページ（講評に辿れない）
  - リンク先は map の値にすぎないので、後から深くするのは定数の差し替えで済む
- **リンク先の持ち方**: `getTaskUrl()`（`src/lib/utils/task.ts`）の先頭で、ダミーの `task_id` をキーにした map を引き、該当すれば jag-icpc.org の URL を返す。問題へのリンクはすべて `getTaskUrl()` を通る（呼び出し元 9 ファイル）ので、1 か所で全画面に効く
  - map は `{ url, taskIds }` をページごとに並べて組み立て、各 URL を 1 回だけ書く
  - URL はブラウザで開けたものをパーセントエンコードのまま貼る（ソースは ASCII のみ）。部品から組み立てない。そのまま返すことを単体テストで固定し、二重エンコードや書き換えを防ぐ
  - ダミーは DB、map はコードにあるので、map の漏れは存在しない AOJ のページへのリンクになる（今の `getTaskUrl()` は JAG の contest_id なら AOJ の `/problems/{task_id}` を返す）。ダミーと分かる `task_id` の接頭辞（採番で決める）と、seed のダミーが全件 map にあることのテストで防ぐ
  - 不採用: Task に `url` 列を足す（マイグレーションと呼び出し元 9 ファイルへの波及があり、クロスレビューの対象にもなる。21 件には重い。他サイトへの対応時に再検討）。URL ジェネレータを足す（`canHandle` が contest_id しか受け取らず、インターフェースの変更が要る）
- **ダミーのリンクの見た目**: 他の問題と同じ見た目だと、AOJ に提出するつもりで開いて jag-icpc.org に飛ぶ。「問題文のみ」などの表示を足すか
- **投票 / タグ / 問題集への登場可否**。FK が `task_id` 参照であるため、ダミーを入れると各機能に波及する
